# Дизайн-паспорт — «Улыбка», бот записи

**Статус:** реализация шага 4 готова к визуальной приёмке. Вариант A выбран владельцем; вариант B сохранён отдельно. Сумму не показывать по решению владельца.

| Решение | Значение |
|---|---|
| Ниша / аудитория | Демонстрация записи в вымышленную стоматологию «Улыбка»; город и адрес не заданы |
| Арт-направление | Клиническая точность, спокойствие, ощущение рабочего прибора |
| Антипример | «Уютная клиника»-спа, зубные эмодзи, стоковые улыбки, псевдо-статистика и обещания медрезультата |
| Одно действие | Пройти интерактивный сценарий записи и увидеть, какое обращение получит администратор |
| Дисплей / текст / цифры | Onest 400/600 для заголовков и текста; JetBrains Mono 400 для коротких служебных меток и времени; максимум 2 семейства |
| Шкала кеглей | 12 / 14 / 16 / 20 / 28 / 44 / 72 px |
| Палитра | Холодный свет `#F1F4F1`, чернильный `#0C1512`, приглушённый `#46564F`, клинический зелёный `#1F6B4A`, поверхность `#E4EBE6` |
| Контраст | Чернила/фон 16,75:1; приглушённый/фон 7,01:1; зелёный/фон 5,81:1; светлый текст/зелёный 6,09:1; чернила/поверхность 15,31:1 |
| Сетка | 12 колонок, контейнер 1240 px; A — текст 5/7 и чат 7/5; B — чат и карточка администратора в широкой спецификации; на телефоне один столбец |
| Радиусы / границы / тени | Поля 4 px, контейнеры 0 px; границы 1 px; без декоративных теней |
| Движение | Только появление нового сообщения снизу 180 ms; отключено при `prefers-reduced-motion` |
| Вариант первого экрана | A: телефон с интерактивным чатом рядом с заголовком / B: рабочая панель «диалог → обращение администратору»; выбран A — первый взгляд сразу показывает знакомый путь записи |
| Крючок | Прямо на первом экране можно выбрать услугу; сценарий — 4 услуги × 4 демонстрационных окна |
| Честность | Клиника, сотрудники, услуги и расписание вымышлены; симуляция не отправляет и не сохраняет введённые данные; медицинских советов и обещаний нет |

## Референсы и компоненты

- `.opencode/skills/web-design/reference/recipes.md` → клиническая точность, холодный свет, глубокий зелёный; переносим ясную структуру, не копируем рекламные утверждения и примеры с недоказанными цифрами.
- `portfolio/design.html` → образ clinic из дизайн-каталога: монохромная типографика, зелёный акцент и форма с ясными состояниями; не копируем карточку один-в-один.
- `portfolio/assets/base.css` → `.ui-btn`, `.ui-input`, `.ui-field`, focus-visible и reduced-motion. Интерактивный чат будет собственным компонентом, потому что этого паттерна нет в библиотеке.

## Варианты первого экрана

### A — iPhone с живым Telegram-диалогом

```text
┌ УЛЫБКА · ДЕМО ───────────── Услуги ─┐
│ Стоматология · демонстрация         │
│ Запись на приём                     │
│ — без звонка                        │
│ 4 услуги · 4 окна · пример          │
│                          ┌────────┐ │
│                          │ бот    │ │
│                          │выберите│ │
│                          │ услугу │ │
│                          └────────┘ │
└ симуляция · данные не отправляются ┘
```

Справа — целиком нарисованное устройство в пропорциях смартфона: графитовая рамка, физические боковые кнопки, статусная строка iOS с Dynamic Island, шапка чата, Telegram-подобный фон переписки, облака сообщений, inline-кнопки бота и нижняя строка ввода с индикатором Home. Выбор услуги открывает четыре условных окна прямо внутри экрана. Слева — заголовок и короткая спецификация без неподтверждённых цифр. Это стилизация интерфейсов iPhone и Telegram, не настоящий скриншот, не приложение Telegram и не подключённый бот.

### B — Панель «диалог → администратор»

```text
┌ УЛЫБКА · ДЕМО ───────────── О записи ┐
│ Демонстрация сценария записи        │
│ Выберите услугу —                   │
│ проверьте каждый шаг                │
├─────────────────────┬───────────────┤
│ живой чат             │ администратору│
│ услуга → время        │ итог выбранного│
│ имя → телефон         │ обращения      │
└─────────────────────┴───────────────┘
```

Горизонтальная рабочая панель показывает не только разговор, но и сформированное из его ответов обращение администратору. Более техническая и наглядно демонстрирует весь путь данных; на мобильном складывается в последовательность «чат → обращение».

Оба варианта — функциональная симуляция в браузере, не макет реального Telegram-клиента и не подключённая система клиники. Ни одно введённое значение не покидает страницу.

## Данные сценария

- 4 демонстрационные услуги: консультация, профгигиена, лечение кариеса, детский приём.
- 4 условных времени; на каждом шаге можно вернуться и изменить выбранное время.
- Имя и телефон проверяются понятными сообщениями; в конце показывается локальная заявка для администратора и её состав.
- Использовать только явно демонстрационные данные; не показывать реальные медицинские рекомендации, диагнозы, врачей и отзывы.
- Фото стойки регистрации из `../assets/clinic-thumb.webp` можно включить только вне Hero и только с подписью «иллюстрация». Вариант без фото допустим.

## Цена пакета — по решению владельца не показывать сумму

`docs/brief-portfolio.md` содержит ориентир Telegram-бота **11 900 ₽ / 3–5 дней**, но прямо помечает его как неподтверждённый. Владелец выбрал не показывать сумму. В демо будет состав работ без цены и срока; исходное требование плана о ценовом блоке изменено.

## Реализация и проверка

- Выбранный экран A: `index.html` — одностраничный Hero с интерактивным чатом в полном макете iPhone/Telegram; вариант B сохранён как отдельная альтернативная композиция в `variant-b.html`.
- В `index.html` встроены CSS и JS, без сборки, зависимостей и серверного API; из общих файлов подключён только `../assets/base.css`.
- Сценарий в браузере: 4 услуги × 4 условных окна, локальная проверка имени и телефона, финальный предпросмотр администратору, возврат и смена времени, перезапуск.
- Проверено через браузер: все 16 пар услуги/времени дали соответствующий предпросмотр; смена времени обновляет итог. Ошибки короткого имени и неправильного номера объясняются под полем. Значения не попали в URL, localStorage или sessionStorage; сетевых вызовов отправки формы нет.
- После проверки телефон нормализуется для отображения; как услуга, имя, время и телефон — только демонстрационные. Введённые данные хранятся лишь в оперативной памяти до перезапуска/закрытия страницы.
- Макет устройства включает рамку и боковые клавиши, status bar / Dynamic Island, шапку чата, сообщения, клавиатуру бота и нижнюю composer-панель; всё нарисовано CSS/HTML, никаких чужих скриншотов и логотипов не используется.
- A11y audit для локальной страницы: Lighthouse доступность 100/100 и best practices 100/100; SEO 80/100 из-за проверки robots.txt на `file://` (это не отдельный robots.txt сайта). Ошибки консоли не выявлены.
- Контраст основных токенов темы clinic: текст/фон 16,75:1; приглушённый текст/фон 7,01:1; зелёный/фон 5,81:1; светлый/зелёный 6,09:1; текст/поверхность 15,31:1.
- Возврат на витрину: первая ссылка в шапке «← Все демо» ведёт на `../index.html`, подчёркнута цветом текста (16,75:1), фокус — рамка 2 px с отступом 3 px. На ≤680 px шапка двухстрочная: логотип и плашка «Демо» сверху, все три ссылки — второй строкой; на ≤380 px плашка сокращается до «Демо» (полный текст остаётся для скринридеров). На 320 / 360 / 390 px горизонтального переполнения нет.
- Ограничение проверки после обновления телефона: локальный предпросмотр 1000 × 700 px показал целиком уменьшенный макет устройства 304 × 562 px; все четыре кнопки первого шага видны, горизонтального переполнения нет. HTTP-предпросмотр на `localhost:8081` вернул 502, поэтому автоматические прогоны ширин 390/768/1440 px и интерактивный мобильный screenshot не выполнены; владелец может открыть HTML двойным кликом для проверки на своём телефоне.
